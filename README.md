## Режимы для ревью

| Параметр | Что делает |
|---|---|
| `.` (клавиша) | Demo panel: сцена hero, переход (Wave / Flip / Fade), **мега-меню** (Closed / Products / Solutions / Resources / Company), автоплей, скорость |
| `?panel` | Открыть demo panel сразу |

| `?shot=hire` / `onboard` / `monitor` / `insights` | + зафиксировать hover-состояние одной колонки |
| `?shot=all` | все колонки how it works в hover = фрейм «how_it_works hover states» |
| `?menu=products` | открыть мега-меню при загрузке (`solutions`, `resources`, `company`) |
| `?search=mvr` | открыть поиск с запросом |
| `?slow=6`, `?fx=flip` | замедлить переходы / тип перехода hero |

## Сверка с макетом

Headless Chrome 1440 (`?shot`) против `get_screenshot` фреймов. Все секции совпадают по высоте в пределах 1px (футер −4px), mean abs diff 1–4 из 255 (антиалиасинг текста). Отдельно сверены: hover-фрейм how it works (4.2), 4 мега-меню (5–8), hero по строкам текста (±1px).

Что пришлось подобрать по замерам:
- **letter-spacing** в токенах Figma задан в процентах: display −3% (−3.48px), h1 −2% (−1.2px)
- **переносы**: Figma использует `text-wrap: pretty` → здесь `text-wrap-style: pretty` (longhand, чтобы не ломать `nowrap` в мини-карточках)
- иллюстрации в колонках не масштабируются, а **сужаются до 336px** при той же высоте 269
- в «See what matters. / Know what to do next.» в макете принудительный перенос

## Дизайн-система (Storybook + MD)

Источник правды: текущий Figma (Page 8) + то, что реализовано на сайте. Состояния, которых нет в макете (hover, focus, поиск, drawer, motion), включены и помечены как site-only.

| Что | Где |
|---|---|
| Токены (W3C DTCG JSON) | `tokens/foley.tokens.json` – единственный источник; site-only токены помечены `$extensions.foley.source: "site"` |
| CSS-переменные | `tokens.css` – генерируется `npm run tokens` (`scripts/build-tokens.mjs`), руками не править; `styles.css` ссылается только на них |
| Storybook | `.storybook/` (html-vite 10.6, addon-docs + a11y + pseudo-states), истории в `ds/` |
| MD-документ | `DESIGN-SYSTEM.md` (EN), он же страница «Design System (MD)» в Storybook |

Как устроены истории: разметка берётся **из `index.html`** (виртуальный модуль `virtual:foley-site`), стили – те же `tokens.css` / `styles.css` / `stages.css`. Правка на сайте сразу видна в DS, рассинхрона нет.
- **Static** истории – клон фрагмента страницы в нужном состоянии (pseudo-states для hover / focus)
- **Live** истории – подключают настоящие `app.js` / `stages.js` (мега-меню, поиск, drawer, hero, карусель, how it works); при переходе между live-историями iframe перезагружается
- Разделы: Introduction, Foundations (Colors, Typography, Layout, Iconography, Motion, Imagery, Accessibility), Components (17), Pages / Homepage, Design System (MD)

Оформление Storybook – по структуре сайта [IBM Design Language](https://www.ibm.com/design/language/), но только на токенах Foley и Inter Display Regular: тёмная полоса сверху (`bg/inverse`), белый сайдбар с пунктами 32px и полосой 4px у текущей страницы, серый фон доков (`bg/secondary`) с тёмной плашкой заголовка (`type/h1`), лид `type/subtitle`, текст 16/24 с шириной колонки 704px, плоские белые блоки превью и таблицы с линиями 1px. Нового контента нет. Превью компонентов остаются со стилями сайта (правила доков ограничены `:not(.docs-story *)`). Файлы: `.storybook/theme.js`, `manager-head.html`, `preview.css`. Изменения `manager-head.html`, `manager.js`, `main.js` подхватываются только после перезапуска Storybook. Виджет «Get started» и тосты «What's new» отключены.

Проверка: `ref/tools/sbcheck.mjs` открывает все истории и docs-страницы (84) и ловит ошибки рендера.

Сборка статикой: `npm run build-storybook` → `storybook-static/` (в .gitignore).

## Мега-меню: заголовки колонок

Заголовок колонки + описание (Hiring and Onboarding, Compliance, …) – одна ссылка `a.mm-head` во всех 4 меню (11 штук). Hover / focus: заголовок подчёркивается слева направо, справа въезжает стрелка. Заголовки колонок тоже попадают в поиск.
